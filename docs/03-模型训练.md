# 03 模型训练

## 1. 关键超参

| 参数 | 值 | 说明 |
|---|---|---|
| `policy.type` | gaussian_actor | 连续动作策略（3 维） |
| `discount` | 0.97 | 折扣率，负责把终点奖励回推到前面每一帧 |
| `latent_dim` | 256 | 网络隐层宽度 |
| `online_steps` | 1000000 | 目标训练步数 |
| `online_step_before_learning` | 10 | 池子里攒够多少条才开始学 |
| `online_buffer_capacity` | 30000 | 在线缓冲池容量 |
| `online_ratio` | 0.5 | 每批数据里在线/离线各占一半 |
| `batch_size` | 256 | |
| `policy_parameters_push_frequency` | 4 | 每 4 秒把策略推给 actor |
| `save_freq` | 1000 | 每 1000 步存一个检查点（约 2.3 分钟） |
| 地图步长 | `0.009 / 0.009 / 0.01` | x/y/z 每步移动多少米 |

## 2. ★★ wandb：必须第一次启动就开

**这条是血泪教训**：训练指标（loss、干预率、回合奖励）**只往 wandb 送**（`learner.py:426` 收集 → `:437` 仅 wandb 开启时输出）。`wandb.enable=false` 时，**终端和日志里一个字都没有**。

更麻烦的是 `resume=true` 会强制 `wandb.init(resume="must")` —— 如果这个 run 从一开始就没开过 wandb，**永远补不上**，续训直接报：

```
RuntimeError: Couldn't get the previous WandB run ID for run resumption
```

**所以：开训前先 `wandb login`，配置文件里 `wandb.enable=true`。** 一旦这轮开了，检查点里会记下 `wandb.run_id`，以后续训自动接着写同一个 run，不用再手动指定。

> 补救只有三条路：① 不带 wandb 续训 ② 删目录从头来 ③ 新 output_dir 热启动。

## 3. 续训

```bash
python -m lerobot.rl.learner \
  --config_path=<output_dir>/checkpoints/last/pretrained_model/train_config.json \
  --resume=true
```

- **`--resume=true` 不能单独用**：会报 `A config_path is expected when resuming`，必须配上指向检查点的 `config_path`
- 续训读的是**检查点里的旧配置**，所以想改 `wandb.*` 之类的必须在命令行覆盖
- actor 那边共用同一个 `validate()`，有检查点后**必须**给它单独指一个 `--output_dir`，否则撞 `FileExistsError`

## 4. 在线缓冲池的语义（很重要）

| 存在检查点里的 ✅ | 只在内存里的 ⚠️ |
|---|---|
| 策略权重（actor 网络） | **在线缓冲池的全部经验** |
| actor / critic 优化器状态 | |
| 温度参数、随机数状态 | |

**结论**：**续训不会白学**（策略水平接着走），但**攒下来的在线经验会丢**，池子要从零重新攒（约 20 分钟）。

> 想让池子跨重启保留需要走"把池子导出成数据集"那条官方代码，而那段本身有 bug（图像 dtype），本项目已禁用它。
> **所以：想彻底不丢池子，就别频繁重启。**

## 5. 检查点管理

- `save_freq=1000`，每个约 40MB
- 跑到 100 万步 ≈ **40GB**，建议定期只留最近几个：

```bash
cd <output_dir>/checkpoints
ls -d [0-9]* | sort -n | head -n -5 | xargs rm -rf   # 只留最近 5 个
```
