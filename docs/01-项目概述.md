# 01 项目概述

## 1. 为什么选 HIL-SERL

模仿学习（ACT / SmolVLA）靠示教数据学，瓶颈很明确：**示教要几十条，而且策略只能达到示教水平，错了不会自己纠**。

HIL-SERL（Human-in-the-Loop Sample-Efficient RL）换了个思路：

- 只要 **10 条左右**示教当"起手式"
- 之后让机械臂**自己跑**，推歪了人或接管一下
- 接管的数据反过来喂给强化学习算法，策略**越跑越不需要人管**

代价是需要实时性问题（learner 和 actor 必须同时跑）和一套正确的工程配置 —— 本项目记录的正是这些。

## 2. 架构：两个进程

| 进程 | 角色 | 说明 |
|---|---|---|
| **learner** | 策略服务器 + 训练 | 持有策略网络，通过 gRPC 把最新参数推给 actor；同时收 actor 传来的 transition 做 SAC 更新 |
| **actor** | 真机执行 + 采集 | 拉参数、驱动机械臂、按 `policy_parameters_push_frequency` 更新本地策略，把 transition 回传给 learner |

两个进程通过 gRPC 通信，**必须同时存在**：

- 只跑 learner → 没有数据进池，空转
- actor 崩了 learner 不会知道 → 会继续"对着空气"推参数（见 docs/05 的坑 5）

## 3. 动作空间：为什么砍成 3 维

官方示例保留 4 维（x, y, z + 夹爪）。本项目**推物体任务全程不用夹爪**，所以：

- 训练时把动作裁到前 3 维（`trainer.py` 补丁）
- actor 侧补回夹爪维度、恒为闭合值（`actor.py` 补丁）

好处：策略少学一个自由度，探索空间更小、收敛更快。

## 4. 任务设计

选「把物体推进黑胶带区」而不是「抓取-放置」，因为：

- **时程短**：一次推 1~2 秒就结束，适合在线 RL 的回合制采样
- **奖励明确**：物体进没进胶带区，人按一下 `y` 就是 1，全程 0
- **探索空间小**：物体起始位置固定，动作范围小

这三条直接决定训练能不能在几十分钟内出效果。
