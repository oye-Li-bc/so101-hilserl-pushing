# 04 部署与迭代

## 1. 部署 = 直接看 actor

LeRobot 有个通用部署 CLI `lerobot-rollout`（"the single CLI for running trained policies on real robots"），**但它接不上 HIL-SERL 策略**：

- 检查点里存的前处理链**只有归一化**，没有裁剪/缩放
- 策略只吃 `[3,128,128]` 的裁剪图
- 只输出 3 维动作，没有 IK、没有夹爪维度

而 HIL-SERL 的裁剪、缩放、逆运动学、EE 围栏这些**全在 actor 侧的处理器链**里。所以：

> **看策略表现 = 直接起 actor**（它就是在真机上部署策略）。人在环的接管用 `空格`。

## 2. 冻结某个检查点当"播放器"

想客观评估某个检查点（比如 21,000 步）的真实水平，需要让 learner **只放一次权重、之后不再学习和推送**。

原理（`learner.py:342 / 412-414`）：

```python
# 循环开始前推一次参数
push_actor_policy_to_queue(...)
...
# 循环里：池子没攒够就直接跳过 —— 不训练、也不推新参数
if len(replay_buffer) < online_step_before_learning:
    continue
```

**所以把门槛设成天文数字即可**：

```bash
python -m lerobot.rl.learner \
  --config_path=configs/train_push_cylinder.json \
  --policy.pretrained_path=<checkpoints>/0021000/pretrained_model \
  --policy.online_step_before_learning=1000000000 \
  --output_dir=<output_dir>/eval_21000 \
  --job_name=eval_21000 \
  --wandb.enable=false
```

再正常起 actor 即可。注意：

- `output_dir` 一定换个新的 → **不会碰训练检查点**
- 关掉 wandb → 不污染训练项目
- 评估时**自己千万别碰键盘** —— 碰了就是"你在开"，测不出策略真实水平

## 3. 干预率怎么读（别被它误导）

```
intervention_rate = episode_intervention_steps / episode_total_steps   # 每集一个点
```

**这个数有一半在量人，不是量 AI**。最容易踩的坑：

> 键位里 **`空格` 才是"交还"**。你中途救了一次、如果没按空格交还 → **从救的那一刻到本集结束，每一步都算你在介入** → 一集只救一次，这个数就是 0.5~0.8。

所以那个数高**不等于策略差**，而且**在驾驶的那段时间，数据里记的是你的动作** —— 救完不交还，策略学到的就变成"照着你的操作抄"。

**正确的读法**：
1. 看 **`Episode intervention`**（0/1，这一集到底需不需要人救）的平均值，比那条抖动的线干净
2. 看**掉到 0 的集**：完全没接管、策略自己完成的集，那才是"学会了"的硬证据
3. 手动测试才是金标准：**换不同起始位置，自己不碰键盘，数成功次数**

## 4. 迭代节奏

| 阶段 | 步数 | 观察 |
|---|---|---|
| 冷启动 | 0~5k | 动作基本是乱的，靠人带 |
| 起步 | 5k~20k | 开始能推出方向，中途常需救 |
| 成形 | 20k~50k | 换起始位置也能自己完成 |
| 泛化 | 50k+ | 干预率显著下降 |

每次改动（换物体、换起始位置、动相机）后**必须重新量三件套**，否则策略的输入分布和你录的数据/围栏全对不上。
